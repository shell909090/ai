# 五个关键事件与触发后动作

协调器由两条事件流共同驱动：Trello 端四个列表入出事件，加上 opencode 端一个会话完成事件。其它列表变化（icebox、done、archived）不参与自动协调。

## 一、卡片进入 todo

人类审稿通过后把卡片从 icebox 拖到 todo。协调器不立即动作，只把卡片记入待调度名单，等下一次扫描 todo 列时由自动推进通路统一做并发检查，再决定是否推到 doing。

## 二、卡片离开 todo

两种来源：人类从 todo 拖回 icebox（撤回审稿）；或者协调器在自动推进时把它推到 doing，这种情况下"进入 doing"会接管，不需要额外动作。

协调器只写一条评论记录这次移动，并从内部记录中清除这张卡。

## 三、卡片进入 doing

三条入口必须行为一致：人类从 todo 拖进来（新卡）、人类从 done 拖回来（验证不通过）、协调器自动推进。统一走五步：

第一步看标签是不是"人工事物"。如果是，协调器直接忽略这张卡，不启动会话、不建工作区、也不做并发检查。人工事物卡在 doing 列是预期状态，由人类直接处理，不该被并发上限拖回 todo。

第二步过并发上限。当前 doing 列卡片数或某个项目的卡数超了，就写一条"并发已满"的评论解释原因，把卡片移回 todo，结束这次处理。不加"需要关注"标签——人类拖卡循环重试本身就是兜底机制。

第三步建立或复用工作区。卡片如果需要改代码，基于当前主分支创建它的专属分支；以前来过就复用并把分支同步到当前主分支。

第四步跑工作区初始化脚本。失败只记警告，会话继续。

第五步启动会话：写启动评论、改会话标题、发提示、调会话管理器。

三条入口的差异只在第一步之后：人类手动拖时 Trello 已经把卡片移到 doing，协调器只响应；人类从 done 拖回来时复用现成工作区并读人类评论；协调器自动推进时自己先调 Trello 移卡，移卡失败就回滚计数不启动。

## 四、卡片离开 doing

三种来源：人类拖回 todo（暂停）；协调器移到 todo（并发超限、会话异常、验证超限）；协调器移到 done（会话完成且验证通过）。

移到 todo 时，协调器先终止会话、清除内存状态，但保留工作区目录和分支（不删，下次回来可以继续）。按原因写评论：人类主动中止写"用户暂停"、会话异常写"会话错误"、验证超限写失败命令和重试次数、并发超限写"并发已满"。

移到 done 时写"完成"评论，保留会话记录和工作区让人类验证。如果是正常完成的会话，完成总结流程会额外写一条摘要评论。除此之外不做其它动作，等人类验证。

## 五、opencode 会话完成

协调器每十秒对每个 doing 卡片的会话做一次探测，读取最新一条消息里的完成字段。这个字段有六个可能的值，**只有五个值真正触发完成流程**——"工具调用中"不是完成信号。

字段缺失说明模型还在流式输出；"工具调用中"说明模型调了工具等工具返回后会继续，这两种情况都跳过等下一轮。"停止"是正常结束，触发完成流程和完成总结。"达到长度上限"、"内容被过滤"、"出错"、"未知值"是异常结束，跳过完成总结、写错误评论、加"需要关注"标签、走完成流程。

### 正常完成（停止）

两阶段。第一阶段是完成总结：协调器向同一个会话发一个固定的中文提示（聚焦"本次运行的结果"），等下一轮完成字段出现（最多一分钟超时），从最新消息里提取文本内容、取前一百四十个字（超出末尾加省略号），写一条"摘要"评论。如果模型没产出可读内容，就写"本次会话未产生可读总结"。

第二阶段是完成流程：写"完成"评论，如果需要工作区就确认主分支有没有变、变了就同步重跑验证，然后跑三件套（构建、检查、单元测试）。通过就把卡片移到 done；失败且没超重试上限就向同一个会话发修复提示（"三件套失败，错误如下：日志。请修复并重试。"），卡片留在 doing，等下一轮完成字段再验证；失败且超限就移到 todo、写失败评论、保留工作区。

总结提示发送失败就跳过总结阶段按原流程走；等待期间卡片被拖出 doing 就走拖出处理；等待超过一分钟就超时跳过总结。

### 异常完成（四个异常值）

跳过完成总结，写"会话错误"评论（带原因和 attach 会话命令），加"需要关注"标签，然后跑三件套和移到 done，等人类 attach 会话调查。这些值表示"模型本轮不再说话"（工具调用除外），发总结提示没有意义。"需要关注"标签是让人类从 opencode 看完整会话的入口。

### 工具调用中或字段缺失

跳过等下一轮。模型调了工具后会继续生成下一条消息，那时会出现新的完成字段。如果把它当作完成就会过早停止协调器对这个会话的监控。opencode 自己也把工具调用判定为"未完成"。

## 事件来源

Trello 端每五秒轮询一次，对比看板快照识别列表变化。opencode 端由完成监听器每十秒探测完成字段。两路统一送入事件总线再进入协调循环。
